## 1. 프로젝트 한 장 요약

**무엇을 하는가**: 올리브영 판매 랭킹을 매일 수집해, **"무엇이 랭킹을 설명하는가"** 를 상품 단위
데이터로 검증한다. 최종 연구 질문 3개:

| 질문 | 내용 | 현재 상태 |
|---|---|---|
| **Q1** | 리뷰 **유입 속도**가 빠른 상품일수록 랭킹이 높은가 | ✅ 강한 증거 확보 (카테고리 내 ρ≈−0.39, 5일 연속) |
| **Q2** | **체험단 비중**이 높으면 랭킹에 유리한가 | ❌ 미검증 — 탐지율 0.34%로 신호 부족 (과제 T5) |
| **Q3** | **리뷰 수 vs 평점**, 무엇이 설명력이 큰가 | ✅ 결론: 규모는 설명, 평점은 설명 못함(천장효과) |

**해석 원칙 (필수 준수)**: 랭킹 상위 표본은 절단 표본이고, "상위 노출 → 리뷰 증가"라는 역인과
경로가 존재한다. 따라서 **모든 결과는 인과가 아니라 연관성·설명력으로만 서술한다.**

**이미 밝혀진 것 (재분석 불필요)**:
- 리뷰 규모(log 리뷰수)는 카테고리×일 고정효과 회귀에서 t=−20.2로 압도적 유의
- 할인율도 유의 (t=−8.2) — 같은 카테고리 안에서 할인 큰 상품이 상위권
- 평점은 고정효과 모형에서도 무의미 (4.7~4.9에 몰린 천장효과)
- 랭킹은 고변동: 일 평균 42개 상품 교체, 월초(8/1)엔 70개 교체로 사실상 리셋
- 상시 랭커 브랜드 31개(전체 252개 중)가 슬롯의 48% 점유, 각자 단일 카테고리 전문
- 썸네일: 상위권일수록 어둡고 채도 높음 — 8/1·8/5·8/9 세 스냅샷에서 부호 재현

## 4. 분석 과제 목록

우선순위 순. 각 과제는 독립 실행 가능하며, **입력 → 방법 → 산출물 → 성공 판정**이 명시되어 있다.

---

### 🔴 T1. 리뷰 "성장률" 분리 — 규모와 속도의 얽힘 해소

**왜 필요한가**: 현재 velocity(일 리뷰 증가분)는 단독 상관이 강하지만(ρ≈−0.39), 고정효과 회귀에
리뷰 규모와 함께 넣으면 약해진다(t=−1.5). 대형 상품이 유입도 많기 때문에 두 변수가 얽혀 있다.
**"규모가 커서 유입이 많은 것"과 "지금 뜨고 있어서 유입이 많은 것"을 분리**해야 Q1이 완결된다.

- **입력**: `data/*_ranking.csv` (8/5~ 카테고리 패널)
- **방법**:
  1. `growth_rate = velocity_delta / 리뷰수` (일일 성장률) 계산 — build_dataset.py에 이미 있음
  2. 대안 지표도 만들 것: `log(1 + velocity)`, `velocity의 카테고리 내 백분위`, `잔차화 속도`
     (velocity를 log_review_cnt에 회귀시킨 잔차 = 규모로 설명되지 않는 순수 속도)
  3. 카테고리×일 고정효과 회귀에 **규모 + 잔차화 속도**를 함께 투입 (VIF 확인, 목표 < 5)
  4. 리뷰 규모 구간별(소·중·대형 상품) 층화 분석 — 속도 효과가 어느 구간에서 나오는지
- **산출물**: `analysis/output/growth_analysis_YYYY-MM-DD.txt` + 보고서 §4.4.2 갱신
- **성공 판정**: 잔차화 속도의 t값이 유의(|t|>2)하면 → "규모와 독립적인 속도 효과 존재" 확정.
  유의하지 않으면 → "속도 효과는 규모의 대리변수였다"는 것도 유효한 결론이니 그대로 서술할 것

---

### 🔴 T2. 카테고리×일 고정효과 회귀 확장 (브랜드 통제 + 표준오차 보정)

**왜 필요한가**: 현재 회귀는 카테고리×일 고정효과만 걸려 있다. 메디힐 한 브랜드가 슬롯의 상당수를
차지하므로 **브랜드 효과가 리뷰 규모 효과로 오인**될 수 있다. 또 같은 상품이 여러 날 반복 등장하므로
표준오차가 과소추정되어 t값이 부풀려져 있다.

- **입력**: `data/*_ranking.csv` (8/5~), 기존 코드는 이전 세션의 인라인 스크립트 → 모듈화 필요
- **방법**:
  1. `analysis/panel.py` 신규 작성 — 카테고리 패널 구축을 재사용 가능한 함수로
  2. 고정효과: 카테고리×일 + **브랜드** (더미 또는 within 변환 2단계)
  3. **상품 단위 클러스터 표준오차** 적용 (같은 상품의 반복 관측 상관 보정)
  4. 변수: log_review_cnt, 잔차화 속도(T1 결과), 할인율, 별점분포(별점1비율 등), 배지 더미
  5. 계수 안정성 확인: 날짜별로 회귀를 돌려 계수가 일관된 부호·크기인지 (rolling coefficient plot)
- **산출물**: `analysis/panel.py`, `analysis/output/panel_fe_YYYY-MM-DD.txt`
- **성공 판정**: 브랜드 통제 후에도 리뷰 규모 계수가 유의하게 남는가. 클러스터 SE 적용 후
  t값이 얼마나 줄어드는지 명시 (보고서 표 11 수치를 이걸로 교체)

---

### 🟠 T3. 진입/잔류 모형 — 순위보다 안정적인 종속변수

**왜 필요한가**: 랭킹이 일 42개씩 교체되는 고변동 시스템이라, "순위 몇 위"보다
**"내일도 TOP100에 남아있는가"**가 더 안정적이고 해석이 명확한 종속변수일 수 있다.

- **입력**: `data/*_ranking.csv` 전 기간 (전체 TOP100 + 카테고리 각각)
- **방법**:
  1. **잔류 로지스틱**: 종속변수 = 익일 랭킹 잔류 여부(0/1). 설명변수는 T2와 동일 + 당일 순위
  2. **진입 분석**: 신규 진입 상품의 진입 직전 특성 — 진입 시점 리뷰 유입 속도가 기존 상품보다
     높은가 (현재 알려진 것: 신규 진입 상품의 중위 리뷰수는 잔류 상품의 1/3)
  3. **생존 분석**: 상품별 TOP100 체류 기간(연속 등장일수)을 종속변수로 Kaplan-Meier / Cox
     — 어떤 특성이 오래 버티게 하는가
- **산출물**: `analysis/survival.py`, `analysis/output/entry_exit_YYYY-MM-DD.txt`
- **성공 판정**: 잔류 로지스틱의 pseudo-R²가 순위 회귀의 R²(현재 0.067)보다 높으면
  → 향후 본분석의 주 종속변수를 잔류로 전환 검토

---

### 🟠 T4. 동적 패널 — 선후관계 접근 (데이터 2주 더 필요)

**왜 필요한가**: 지금까지는 전부 동시점 상관이다. **"리뷰가 몰린 다음에 순위가 오르는가,
순위가 오른 다음에 리뷰가 몰리는가"**를 구분해야 Q1이 인과에 가까워진다.

- **선행 조건**: 카테고리 패널 **최소 3주치**(8/5 기준 8/26 이후 권장). 그 전엔 시차 변수의
  검정력이 부족하니 무리하게 돌리지 말 것
- **방법**:
  1. `Δ순위_t = f(velocity_{t-1}, 순위_{t-1}, 통제변수)` — 전기 유입이 당기 순위 변화를 예측하는가
  2. 역방향도 반드시 확인: `velocity_t = f(순위_{t-1}, ...)` — 순위가 리뷰를 부르는 경로의 크기
  3. 두 방향 계수 비교로 **피드백 루프의 상대적 강도** 서술 (Granger 인과 스타일, 단 인과 주장 금지)
  4. 동적 패널의 편의 문제(Nickell bias) 인지 — 시계열이 짧으면 시차 종속변수 계수가 편향됨을 명시
- **산출물**: `analysis/dynamic_panel.py`, 보고서 신규 절
- **성공 판정**: 양방향 계수의 크기 비교가 가능하면 성공. 한쪽만 유의해도 유의미한 발견

### 🟡 T5. 체험단 탐지율 개선 — Q2 검증의 선행 과제

**왜 필요한가**: Q2는 세 질문 중 유일하게 **미검증**이다. 현재 본문 키워드 매칭으로 66,189건 중
222건(0.34%)만 잡혀 회귀에 넣을 분산 자체가 없다. **탐지 문제이지 수집량 문제가 아니다.**

- **입력**: `data/*_reviews.csv` + `data/backfill/top100_reviews.csv` (유니크 리뷰 약 6.6만 건)
- **방법** (단계적, 앞 단계만으로 충분할 수 있음):
  1. **키워드 확장**: 현재 8개(`scraper/config.py`의 `TRIAL_KEYWORDS`)를 확장.
     후보: "제공 받고", "지원받아", "체험 기회", "리뷰어 선정", "당첨되어", "브랜드로부터",
     "업체로부터", "무상제공", "유료 광고", "소정의" 등. 매칭 사례를 눈으로 확인하며 반복 확장
  2. **위치 가중**: 표기 문구는 리뷰 첫/마지막 문장에 몰리는 경향 → 위치 정보 활용
  3. **수동 검증**: 무작위 200건을 직접 읽고 라벨링 → 키워드 룰의 정밀도/재현율 측정
  4. (선택) LLM 분류: `analysis/classify_thumbnails.py`와 같은 방식. ⚠️ **유료 API이므로
     사용자 승인 없이 실행 금지**
- **산출물**: `scraper/config.py`의 키워드 갱신, `analysis/output/trial_detection_eval.txt`
- **성공 판정**: 탐지율이 2~3% 이상으로 오르고 수동 검증 정밀도 80%+ 이면 Q2 회귀 진입 가능.
  **개선 후에도 신호가 약하면 "본문 기반으로는 탐지 불가"를 결론으로 명시**할 것 (실패도 결과다)
- **해석 주의**: 표기를 사진에만 넣은 리뷰는 원리적으로 탐지 불가 → 항상 **하한 추정치**로 서술.
  대안 지표로 "노출면(도움순 상위) 내 체험단 비중"을 병행

### 🟡 T6. 썸네일 마케팅 속성 분석 (수집 PC에서 실행)

**왜 필요한가**: 8/5 수동 라벨 91장에서 **상위권일수록 기간 한정 특가·증정 구성 소구가 많고,
1위·어워즈 클레임은 오히려 하위권에 많다**는 패턴이 나왔다(ρ≈0.13~0.17). N=91 단일 스냅샷이라
확정은 못 했지만, 확인되면 **"프로모션 진행 여부"의 관측 가능한 프록시**가 되어 회귀 통제변수로 쓸 수 있다.

- **입력**: 수집 PC의 `data/images/` + `analysis/labels/img_labels_2026-08-05.csv`(정답지 91장)
- **⚠️ 실행 위치**: 이미지는 리포에 없으므로 **수집 PC에서 실행**하거나, 특성 추출 결과 CSV만
  받아서 분석. `python -m analysis.image_features --date YYYY-MM-DD` 로 저수준 특성 추출
- **방법**:
  1. 저수준 특성(밝기·채도·엣지 등)의 3스냅샷 재현 결과를 더 많은 날짜로 확장
  2. 마케팅 속성(인간모델/캐릭터/기간소구/클레임/증정) 라벨을 더 확보 — 세션에서 컨택트시트를
     보고 수동 라벨링하는 방식이 무과금. 정답지 91장과 기준을 반드시 일치시킬 것
  3. 라벨이 300장 이상 쌓이면 회귀에 투입 (기간소구 더미 = 프로모션 통제변수)
  4. (선택) OCR로 오버레이 텍스트 추출 → "1위", "1+1", 날짜 패턴 정규식 매칭
- **산출물**: `analysis/labels/img_labels_YYYY-MM-DD.csv` 추가분, 보고서 §4.6 갱신
- **성공 판정**: 라벨 300장 + 두 날짜 이상에서 부호 재현되면 통제변수로 채택

### 🟡 T7. 썸네일 교체 이벤트 스터디 (데이터 축적 대기)

**왜 필요한가**: 이미지 파일명이 URL 해시라 **썸네일이 교체되면 전/후 버전이 모두 보존**된다.
같은 상품의 `대표이미지URL` 변경 = 교체 이벤트로 감지 가능하며, 이건 **상품 내 비교(within-product)**
설계라 앞의 모든 크로스섹션 분석보다 인과에 가깝다.

- **입력**: `data/*_ranking.csv`의 `대표이미지URL` 시계열 (이미지 파일 없이도 URL만으로 감지 가능)
- **방법**:
  1. 상품별 URL 변경 시점 탐지 → 이벤트 목록 작성
  2. 교체 전후 ±7일 순위 궤적 비교 (이벤트 스터디, 대조군 = 미교체 상품)
  3. 교체 이벤트가 프로모션 시작과 겹치는지 확인 (혼입 요인 통제 필요)
- **산출물**: `analysis/thumbnail_events.py`
- **성공 판정**: 이벤트 30건 이상 확보 시 분석 착수. 그 전엔 이벤트 수만 집계해 리포트

리뷰·프로모션 분석을 세 갈래로 확장했다. 모두 `python -m analysis.<모듈>` 로 재실행되며
결과는 `analysis/output/*.txt` 로 저장된다.

| 모듈 | 무엇을 하는가 | 보고서 |
|---|---|---|
| `review_quality.py` | 평점을 평균이 아닌 **분포**로 재집계. 긍정(4점↑)·부정(2점↓) 비중을 두 표본(수집 본문 / 사이트 집계)으로 교차확인하고, 브랜드별 산포와 순위 설명력을 검정 | 5.10절 |
| `discount_typology.py` | 카테고리×가격 3분위 셀별 할인 반응 곡선을 추정하고, **진폭을 지운 형태**로 k-means 군집화해 4개 유형 도출 → 유형별 상품 프로파일 | 5.5절 |
| `counterfactual.py` | 배지 온셋 전후 창을 잘라 반사실 5종(사전평균/DiD/ARIMA/MARS 근사/MLP)을 경합시키고, **통제군 홀드아웃 예측오차로 모형을 고른 뒤** 증분 효과를 산출 | 5.6절 |

**설계 노트**

- 세 모듈 모두 `growth.build_panel()` 을 재사용하므로 패널 구축 규약(카테고리 패널만, `전체` 제외,
  상품×일 중복 제거)이 자동으로 지켜진다.
- `discount_typology` 는 상품 내 할인율 변동이 거의 없다는 사실(상품 내 표준편차 중앙값 0)을 먼저
  출력해 셀 단위 설계의 근거를 남긴다. 관측 창이 길어져 상품 내 변동이 확보되면 상품 단위 곡선으로
  승격하는 것이 다음 단계다.
- `counterfactual` 은 실행에 수 분 걸린다(ARIMA를 이벤트마다 적합 + 창 길이 민감도 3회 재적합).
  창 길이는 `--pre` / `--post` 로 조정한다.
